# Complete and preserve an evaluation

Use this procedure when an evaluation spans workers or when publishing the final
decision. It supplements the environment’s runbook; it grants no deployment,
traffic interruption, paid API, messaging or public-upload authority.

## Reconcile before acting

1. Read the run’s contract, exact candidate manifest and current execution state.
   Inspect live units/processes and result exit receipts before launching anything.
   Identify who owns the next transition; a settled child can coexist with an
   active parent that already queued later phases.
2. Build a candidate-by-phase inventory from actual artifacts: matched performance
   shapes, complete task/seed coverage, unchanged grader outputs, combined context
   correctness, actual clients and operational checks. Missing required evidence
   remains work. An observer timeout or failed idle precondition does not erase
   completed measurements or establish model failure.
3. Repair the actual failing component and resume the smallest unfinished step.
   Separate transport recovery, grader rebuilds and observer repairs from model
   quality. Finish authorized decision-changing measurements before publication;
   do not answer a request to evaluate with a non-recommendation caused by work
   that was never performed.

## Make the decision reviewable

Use one candidate identity across tables, flags and prose. Place total/active
parameters, component quantization, KV precision, topology, quality denominators,
TTFT, complete-response latency and tested concurrency/context combinations in
the same comparison. Show cache-hit variability and failed attempts. Distinguish
sample SD across repeated run means from variation among correlated requests.

Match the conclusion to the workload. A new configuration may improve short or
cached turns while losing cold concurrent requests or code correctness. Say that
plainly, including advantages the original retains. A request to pick among new
candidates still needs a concrete selection from the qualified set; it does not
require claiming an overall upgrade over the control. Do not invent a weighted
score or universal quality gate after seeing the results.

Fixed-token inference, scored multi-turn batch wall time and actual-client task
completion are different measures. Label the output budget, cache condition,
correctness and repetition unit of each. A single whole-batch elapsed value is
not three independent timing repetitions merely because it contains three
quality trials. Retain upstream scores and separately linked adjudications.

Keep optional routing/engine follow-ups separate from the primary comparison.
State exactly which one is selected, its completed checks, and which unchanged
quality results carry over. A failed hypothesis is a useful completed result;
an unfinished variant cannot silently replace a qualified primary.

## Close the run

Verify the original restoration and cleanup described in
[temporary trials](operations.md), including the final ordinary client request
after helpers are gone. Keep recommendation, temporary serving, restored live
configuration and permanent deployment as separate fields. Preserve any reserved
permanent-deployment confirmation. Mark execution state terminal only when
required measurement, restoration, cleanup and publication are complete; clear
future launch queues so a watcher does not restart finished work.

## Publish a durable, bounded record

Save a dated report at the consumer’s existing evidence owner. Include the
selected configuration and reasons, comparison conditions, exact manifests and
upstream pins, derived tables, score denominators/recovery policy, failure audits,
uncertainty, restoration proof and source/artifact checksums. Link it from the
owner’s entry point. A dated report is not a current deployment declaration.

Keep full traces, ordinary-traffic logs, credentials, isolated SDK state and
private recovery bundles in protected storage. Retain only bounded supporting
data in Git; link the raw collection and its manifest. Scan the actual selected
publication files and decompressed archives using the environment’s credential
procedure. Check destination visibility before importing private environment
facts into a public skill repository.

Generate tables from one authoritative derived dataset. Verify static values,
all interactive scenarios, relative links and serving-user file access. Record
what was actually tested: DOM checks do not establish visual browser rendering,
and an authentication response is not proof of a missing file. Remove pending
claims left from intermediate phases and keep superseded screening labeled.

Promote general lessons to this skill’s relevant reference and run template;
keep machine names, model pins and incident history with the consumer. Validate
new procedures on comparable, bounded fixtures before claiming better agent
behavior. Structural checks alone establish document consistency.
